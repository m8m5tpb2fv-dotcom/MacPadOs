# MacPad — состояние проекта и что осталось сделать

Этот файл описывает текущую стадию разработки для Claude Code. Прочитай его целиком, прежде чем менять код.

## Что это за проект

MacPad — Android-лаунчер (домашний экран) в стиле macOS для планшета Honor Pad 10: физическая клавиатура, сенсорный экран, иногда мышь.

- Язык: Kotlin. Интерфейс создаётся программно на Android Views. Jetpack Compose и XML-разметку не используем.
- Package и applicationId: `com.macpad.macpad`. Их не менять.
- `compileSdk`, `minSdk` и `targetSdk` равны 36 (Android 16). API до 36 можно вызывать без проверки версии.
- Gradle 9.6.1, AGP 9.3.1, Kotlin 2.3.21. Версии не менять.
- Новые зависимости не добавлять: проект должен собираться офлайн в CodeOnTheGo на планшете.
- Сборка: `sh ./gradlew assembleDebug`. APK появляется в `app/build/outputs/apk/debug/app-debug.apk`.
- Быстрая проверка компиляции: `sh ./gradlew :app:compileDebugKotlin --console=plain -q`.
- На планшете проект лежит в `/storage/emulated/0/CodeOnTheGoProjects/MacPad`. Папка может называться `MacPad ` с пробелом в конце, её не переименовывать.
- Ветка с работой: `claude/admiring-cerf-lw2c12`. В `main` лежит исходный прототип.
- `release.keystore` и `release.properties` в git не входят и входить не должны (они в `.gitignore`).

## ❌ Что НЕ сделано (следующие шаги по порядку)

Эти файлы пока **заглушки**. Публичный API у них уже правильный, его вызывает `MainActivity`, но внутри пусто (`TextView` или пустые методы). Подробные ТЗ лежат в **`docs/COMPONENT_SPECS.md`**: сначала прочитай раздел «Общие правила», затем раздел нужного компонента.

1. **`FinderWindow.kt`** — файловый менеджер, наследник `MacWindow`. Работает только через Storage Access Framework: папки из `prefs.finderPlaces` и `FinderPlaces.add` после `host.pickFolder`. Нужны:
   - боковая панель «Места»;
   - вид «список» (ListView) и вид «значки» (GridView);
   - сортировка;
   - назад, вперёд и «вверх»;
   - поиск по имени (живой фильтр и рекурсивный поиск по Enter);
   - открытие файла через `ACTION_VIEW` (тип из MIME, флаг `FLAG_GRANT_READ_URI_PERMISSION`);
   - «Открыть с помощью…», «Поделиться», «Переименовать», «Удалить», «Новая папка», «Свойства»;
   - понятное сообщение, если доступ отозван;
   - экран приветствия, если папок нет;
   - миниатюры изображений.

   Сохрани API `openPlace(uri: String)`. Состояние держи в полях, чтобы `rebuild()` (смена темы) не перезапрашивал данные.
2. **`SettingsWindow.kt`** — настройки в стиле System Settings: боковая панель с разделами и карточки с настройками. Сохрани `companion` с `ID` и `SECTION_*` и метод `showSection()`. Разделы:
   - Оформление: тема, размер значков, дата в меню, скрытие строки состояния, уменьшение движения;
   - Обои: миниатюры из `Wallpapers.catalog`, «Системные», «Своё изображение» через `host.pickWallpaperImage()`;
   - Dock: размер значков (SeekBar), увеличение, подписи, список закреплённых с кнопками ↑ ↓ ✕, «Добавить приложение…», «Вернуть по умолчанию»;
   - Рабочий стол;
   - Finder (папки с доступом);
   - Главный экран: `host.requestDefaultLauncher()`, количество приложений, «Обновить список»;
   - Клавиатура;
   - О MacPad.

   Каждое изменение сразу сохраняется в `host.prefs`, затем вызывай `host.applySettings()`, `host.onDockChanged()` или `host.onDesktopChanged()`.
3. **`InfoWindows.kt`** — три окна:
   - `AppInfoWindow`: значок, версия, даты установки и обновления, целевой API, размер APK, кнопки «Открыть», «Dock», «Рабочий стол», «Сведения в Android»;
   - `AboutWindow`: модель, Android, процессор, экран, ОЗУ, хранилище, батарея;
   - `ShortcutsWindow`: точный список горячих клавиш (он есть в спецификации и должен совпадать с `MainActivity.handleShortcut`).
4. **`NotesWindow.kt`** — простой TextEdit:
   - автосохранение в `prefs.notesText` с задержкой;
   - «Открыть…», «Сохранить», «Сохранить как…» через SAF (`host.pickFile`, `host.createDocument`);
   - размер шрифта и моноширинный шрифт;
   - счётчик слов;
   - Ctrl+S, Ctrl+Shift+S, Ctrl+O в `handleKey`.
5. **`DesktopIcons.kt`** — ярлыки на рабочем столе (`DesktopIconsLayer`):
   - сетка от верхнего правого угла;
   - тап запускает приложение;
   - долгое нажатие или правый клик открывает `host.showAppContextMenu`;
   - перетаскивание со снапом к ячейке и обменом местами;
   - позиции сохраняются в `prefs.desktopItems`;
   - меню пустой области рабочего стола;
   - `addApp`, `removeApp`, `arrange`.

   Тап по пустому месту должен вызывать `host.windows.deactivateAll()`.
6. **Ревью кода всего проекта** после того, как п. 1–5 готовы: утечки, главный поток, жизненный цикл, крэши, неработающие элементы интерфейса.
7. **Проверка на Honor Pad 10.** На реальном устройстве ничего ещё не проверялось. Список проверок ниже.

## Правила (из ТЗ пользователя, обязательны)

- Не начинать проект заново и не удалять рабочий код без причины. Ядро и контракты из таблицы выше не менять без крайней необходимости.
- Никаких фиктивных функций: каждый видимый элемент интерфейса должен реально что-то делать. То, что невозможно через публичные Android API, не показывать.
- Тяжёлую работу (ввод-вывод, запросы к ContentProvider, рендер картинок) не выполнять в главном потоке. Используй свой Executor и возвращай результат через Handler главного потока. Устаревшие результаты и результаты после закрытия окна игнорируй.
- Не допускать падений: запуски Intent и вызовы SAF оборачивать в try/catch и показывать понятное сообщение на русском (`host.toast` или `host.dialogs.alert`).
- Весь текст интерфейса на русском. Стиль macOS: скругления, тонкие разделители, токены из `host.palette`, поддержка светлой и тёмной темы. Метод `rebuild()` или `applyPalette()` пересоздаёт view.
- Клавиатура: у каждого интерактивного элемента виден фокус (`stateBackground`). Стрелки, Enter и Esc работают. Мышь: hover и правый клик (`setOnContextClickListener`, но не на дочерних элементах AdapterView).
- Учитывай `host.animationsEnabled`.
- Отписывайся от всех слушателей и ресиверов, которые зарегистрировал.
- Сторонние Android-приложения нельзя открыть внутри окон MacPad: Android этого не позволяет. Они запускаются обычным способом.
- Не добавлять разрешения без необходимости. QUERY_ALL_PACKAGES не нужен. Широкий доступ к хранилищу не запрашивать, только SAF.
- После каждого компонента: `sh ./gradlew :app:compileDebugKotlin`, затем коммит.

## Что нужно проверить на планшете (не проверено ни разу)

- Список приложений полный, без дублей, отсортирован, совпадает с системным меню приложений.
- Запуск приложений, включая те, что раньше не запускались. Сообщение при ошибке запуска. Приложения рабочего профиля и клоны («Двойные приложения» Honor).
- Установка и удаление приложения при открытом MacPad: список обновляется.
- Поворот экрана: окна остаются на месте, раскладка Dock и строки меню корректна.
- Горячие клавиши: Ctrl+Space (Android может перехватывать его для смены раскладки, тогда Alt+Space), F4, Ctrl+W, Ctrl+M, Ctrl+N, Ctrl+`, F10, Ctrl+F3, Esc.
- «Сделать MacPad главным экраном» и поведение кнопок «Домой» и «Назад».
- Стекло и размытие на реальных обоях; системные обои (без размытия).
- Скорость: открытие Launchpad, плавность анимаций, память при 150+ приложениях.
- Строка меню: сеть, батарея, часы, переключение меню наведением мыши.
- `minSdk` = 36: APK установится только на Android 16. Так было и в исходном прототипе. Если на планшете Android ниже, нужно снижать `minSdk` и проверять API.

## Известные ограничения (это не ошибки)

- Стекло размывает только обои, не окна под панелью.
- Индикаторы «приложение запущено» в Dock показываются только для внутренних окон MacPad. Для сторонних приложений надёжных публичных данных нет.
- Имя сети Wi-Fi (SSID) не показывается: для этого нужно разрешение на геолокацию.
