# MacPad — спецификации незавершённых компонентов

Исходные технические задания (на английском), по которым делались компоненты. Ядро и контракты уже в коде; ниже — общие правила и подробные ТЗ для компонентов, которые ещё являются заглушками.

## Общие правила для любого компонента

```text
You are implementing ONE component of "MacPad", an existing Android launcher app (Kotlin, programmatic Android Views, NO Compose, NO XML layouts) that turns an Android tablet (Honor Pad 10, landscape, physical keyboard + touch, maybe mouse) into a macOS-style desktop. Package: com.macpad.macpad. compileSdk/minSdk/targetSdk = 36 (Android 16) — you may use any API up to 36 without version checks.


FIRST read these core files carefully (they are the contract; they are final):
- DesktopHost.kt (everything you may call on "host"), MainActivity.kt (how your component is created/used, global shortcuts), Ui.kt (dp(), label(), roundRect(), stateBackground(), applyPressScale(), macButton(), glyphButton(), macTextField(), MacSwitch, MacSegmented, GlassDrawable, Glyph/GlyphDrawable, BatteryDrawable, BuiltinIcon, IconRenderer, withAlpha/lerpColor/blendOver, hairlinePx, Fonts), Theme.kt (Palette tokens), Prefs.kt (MacPrefs, DesktopItem, FinderPlace), Places.kt (FinderPlaces.add/remove/hasAccess/displayName), AppRepository.kt (AppEntry, search, launch, defaultDockKeys, findByKey/findByPackage, addListener), MacMenu.kt (MenuEntry, host.menus.show/showAtScreen), Dialogs.kt (host.dialogs.show/confirm/prompt/alert), WindowSystem.kt (MacWindow base class & WindowManager), Wallpaper.kt (Wallpapers.catalog/render, GlassSource).
Also read the current stub of the file(s) you own: its public API is the contract with MainActivity and other components.

HARD RULES
1. Only create/modify the file(s) you own (listed below). Do NOT modify core files, other components, Gradle files, the manifest or resources. Do NOT add dependencies (only Android framework + androidx.appcompat/core/activity already on the classpath; the project must keep building offline on the device). If you need a helper, write it privately inside your own file (use 'private' / unique names to avoid clashes with other components being written in parallel). If you believe a core change is truly required, do NOT make it — describe it in coreRequests.
2. Keep every public member of your stub with the same signature (you may add more public members).
3. All UI strings in Russian. Visual style: modern macOS (Ventura/Sonoma) — tidy spacing, rounded corners, hairline separators, translucent glass where the core provides it (GlassDrawable over host.glass), consistent palette tokens from host.palette, sizes adapted for touch (min ~36dp targets). Support light & dark palettes (rebuild views in applyPalette()/rebuild()).
4. NO fake features: every visible control must do something real. If something is impossible via public Android APIs, do not show it.
5. Never block the main thread with IO or heavy work: use a private single-thread Executor and post results back with a main-thread Handler; ignore stale results (generation counter) and results arriving after close.
6. Never crash: wrap Intent launches / content-provider calls / permission-dependent calls in try/catch and show a clear Russian message (host.toast or host.dialogs.alert).
7. Keyboard: every interactive element focusable with a VISIBLE focus indicator (use stateBackground or similar); arrow keys/Enter/Esc behave sensibly. Mouse: hover states; right-click = context menu via View.setOnContextClickListener where it does not break normal clicks.
8. Respect host.animationsEnabled for animations (skip/shorten when false).
9. Lifecycle hygiene: unregister receivers/callbacks/listeners you register; no leaks of Activity references in static fields; no infinite Handler loops.
10. Code style: idiomatic Kotlin, matching the existing core style (KDoc on classes/public functions, concise comments only where useful).

BUILD CHECK (mandatory, repeat until clean):
  export ANDROID_HOME=/opt/android-sdk; sh ./gradlew :app:compileDebugKotlin --console=plain -q
It must finish with zero errors. Also eliminate warnings that come from your file(s).
```

## FinderWindow.kt — файловый менеджер (Finder)

Файлы: `app/src/main/java/com/macpad/macpad/FinderWindow.kt`

```text
YOU OWN: FinderWindow.kt — class FinderWindow(host: DesktopHost, id: String) : MacWindow(host, id). Keep: openPlace(uri: String). Override: icon = BuiltinIcon.FINDER, defaultWidthDp 820, defaultHeightDp 520, minWidthDp 440, minHeightDp 300, showsCenteredTitle = false (the toolbar shows the folder name). Keep ALL state in fields (current place, path stack, back/forward stacks, listing, selection, view mode, search query) so that rebuild() (theme change; it calls onCreateContent()/onCreateToolbar() again) re-creates views from state WITHOUT re-querying unless needed. Set 'title' to the current folder name (Window menu uses it). Note: openPlace() may be called right after construction+build (before or after the first listing finishes) — handle that.

STORAGE MODEL — Storage Access Framework only (no broad storage permissions, no file:// URIs):
 - Locations = prefs.finderPlaces (tree URIs granted via ACTION_OPEN_DOCUMENT_TREE). Add via host.pickFolder { uri -> if (uri != null) { val p = FinderPlaces.add(host.context, host.prefs, uri); navigate to it } }. Remove via FinderPlaces.remove(...).
 - Listing a folder: DocumentsContract.buildChildDocumentsUriUsingTree(treeUri, parentDocumentId), projection: COLUMN_DOCUMENT_ID, COLUMN_DISPLAY_NAME, COLUMN_MIME_TYPE, COLUMN_SIZE, COLUMN_LAST_MODIFIED, COLUMN_FLAGS. Root docId = DocumentsContract.getTreeDocumentId(treeUri). Document URI = DocumentsContract.buildDocumentUriUsingTree(treeUri, docId). Folders: mime == Document.MIME_TYPE_DIR. Also query the current folder's own flags (for FLAG_DIR_SUPPORTS_CREATE). Run queries on a private single-thread executor; post to main; drop stale results (generation counter) and results after onClosed().
 - Path stack: list of (docId, name) from the place root, so "up" = pop (works for any provider).
 - Hidden files (name starting with '.') are hidden unless prefs.finderShowHidden.
 - Sorting: folders first, then by prefs.finderSortBy ("name" Collator / "date" / "size" / "kind") with prefs.finderSortDescending. Changing sort/view mode updates prefs.
 - Opening a file: Intent(ACTION_VIEW).setDataAndType(docUri, mime).addFlags(FLAG_GRANT_READ_URI_PERMISSION or FLAG_ACTIVITY_NEW_TASK); on ActivityNotFoundException show host.dialogs.alert("Не удалось открыть файл", "Нет приложения, которое умеет открывать файлы этого типа (<mime>)."). "Открыть с помощью…" uses Intent.createChooser.
 - Errors: SecurityException / revoked permission (also check FinderPlaces.hasAccess) -> inline message in the content area: "Нет доступа к папке «<name>». Разрешение было отозвано." with buttons "Предоставить доступ снова" (host.pickFolder -> FinderPlaces.add) and "Убрать из боковой панели". Other exceptions -> inline error text + "Повторить".
 - Welcome state (no places at all): illustration (big Glyph.FOLDER in accent), text "Добавьте папку, чтобы просматривать файлы. MacPad видит только папки, к которым вы дали доступ." and buttons "Добавить папку…" (pickFolder) and "Открыть файл…" (host.pickFile(arrayOf("*/*")) -> open it with ACTION_VIEW).
 - Initial location: the first place if any (or the place passed via openPlace), else the welcome state.

LAYOUT:
 - Toolbar (onCreateToolbar, horizontal, fills the title bar after the traffic lights): back (Glyph.CHEVRON_LEFT) and forward (CHEVRON_RIGHT) glyphButtons (disabled = alpha 0.35 and not clickable when stacks are empty); the current folder name label (semibold 14sp, ellipsized); a weight-1 spacer; view toggle (two glyphButtons LIST / ICONS, the active one selected); sort button (Glyph.SORT -> menu: "По имени", "По дате изменения", "По размеру", "По типу" (checked), Separator, "По убыванию" (checked)); "+" button (Glyph.PLUS -> menu: "Новая папка…" (enabled when the current folder supports create), "Добавить папку в боковую панель…", "Открыть файл…"); search field (macTextField with Glyph.SEARCH, ~180dp wide, hint "Поиск").
 - Content: horizontal split. Sidebar (~190dp, palette.windowSidebar background): section header "Места" (11sp semibold palette.textTertiary); one row per place (Glyph.FOLDER in accent + name; selected = current place, use selection background with onSelection text); long-press/right-click on a place -> menu "Открыть в новом окне" (host.openFinder(newWindow = true, placeUri = it.uri)), "Убрать из боковой панели" (FinderPlaces.remove + if current, go to another place/welcome); a row "Добавить папку…" (Glyph.PLUS). Section "Устройство": "Открыть файл…" row; and a "Файловый менеджер" row ONLY if one of these packages has a launchable entry: com.hihonor.filemanager, com.google.android.apps.nbu.files, com.google.android.documentsui, com.android.documentsui (use host.apps.findByPackage) -> host.launchApp(entry). Sidebar rows are focusable. Hide the sidebar when the window is narrower than ~600dp (toolbar gets a Glyph.SIDEBAR toggle button that shows/hides it).
 - Main area (palette.windowBg): list or grid view of the current folder, plus a bottom status bar (hairline on top, 12sp palette.textSecondary): "<N> объектов" (correct Russian plural forms: 1 объект, 2-4 объекта, 5+ объектов) and, when searching, "Результаты поиска: N".
 - LIST view: header row with sortable columns "Имя", "Дата изменения", "Размер", "Тип" (tap a header to sort by it; tap again toggles descending; small arrow indicator); rows ~34dp: file icon (20dp), name, date (DateFormat medium date + short time), size (android.text.format.Formatter.formatShortFileSize; "—" for folders), kind ("Папка", "Изображение JPEG", "Документ PDF", "Видео MP4", "Аудио MP3", "Текст", "Архив ZIP", "Приложение Android", otherwise "<EXT>-файл" or "Документ"). Hide date/kind columns when the main area is narrower than ~560dp. Use a ListView + BaseAdapter with convertView recycling; selection highlight (palette.selection/onSelection) for the selected row.
 - GRID view: GridView + BaseAdapter: icon 56dp + name (2 lines); for images/videos load thumbnails via DocumentsContract.getDocumentThumbnail(contentResolver, docUri, Point(px,px), null) on the executor with a small LruCache (by uri), only when the document has FLAG_SUPPORTS_THUMBNAIL.
 - File icons: private drawable built from Glyphs with type colours: folder = Glyph.FOLDER in palette.accent (with a light accent rounded background behind), image = IMAGE (green), video = VIDEO (purple), audio = MUSIC (pink), pdf = PDF (red), archive = ARCHIVE (orange), apk = APP (green), text/code = DOC/CODE (grey-blue), other = DOC (grey).
INTERACTION:
 - Tap a row/cell: folders -> navigate into; files -> open (touch-friendly single tap). Selection is shown for keyboard/long-press.
 - Long-press or right-click on an item -> select it and show a menu: "Открыть", "Открыть с помощью…", "Поделиться" (ACTION_SEND with EXTRA_STREAM + type + FLAG_GRANT_READ_URI_PERMISSION, chooser; files only), Separator, "Переименовать…" (enabled if FLAG_SUPPORTS_RENAME; host.dialogs.prompt(… initial = name, confirmText = "Переименовать") -> DocumentsContract.renameDocument on the executor -> reload), "Удалить…" (enabled if FLAG_SUPPORTS_DELETE; host.dialogs.confirm("Удалить «name»?", "Это действие нельзя отменить.", "Удалить", destructive = true) -> DocumentsContract.deleteDocument -> reload), Separator, "Свойства" (host.dialogs.alert with name, type, size, modified date, location (folder path from the stack)). For list/grid AdapterViews use setOnItemLongClickListener for long-press; for right-click use an OnGenericMotionListener / onTouch check of MotionEvent.BUTTON_SECONDARY with pointToPosition — do NOT set OnContextClickListener on adapter children.
 - Long-press/right-click on empty space in the main area -> menu: "Новая папка…" (if supported; prompt name "Новая папка" -> DocumentsContract.createDocument(cr, parentDocUri, Document.MIME_TYPE_DIR, name) -> reload), "Обновить", Separator, "Вид: список" / "Вид: значки" (checked), sort items as in the toolbar menu.
 - Search: typing filters the current folder's listing by name (case-insensitive contains, live). Pressing Enter in the search field starts a recursive search from the current folder (background, depth ≤ 8, max 500 results, cancellable via generation counter; show "Поиск…" in the status bar); results show the parent folder name as subtitle/kind ("в «Папка»"); tapping a folder result navigates to it (rebuild the path stack from the search walk), file results open. Esc while the search field has text -> clear it and return to the normal listing (return true from handleKey for KEYCODE_ESCAPE in that case, otherwise false).
 - focusSearchField(): focus the search field, select all, return true.
 - handleKey(event) (ACTION_DOWN, called by MainActivity for Ctrl/Meta combos and Esc when the window is active): Ctrl+Shift+N new folder; Ctrl+R refresh; Ctrl+I properties of the selection; Ctrl+O open selection; Ctrl+Up go to parent; Ctrl+[ back; Ctrl+] forward; Ctrl+Backspace delete selection (with confirmation). Also make plain keys work when the list/grid has focus (OnKeyListener on the list/grid): Enter opens, Backspace / Alt+Left back, Alt+Right forward, Delete / FORWARD_DEL deletes the selection (with confirmation), F5 refresh.
 - Back/forward/up navigation keeps the selection of the folder you came from when possible.
 - openPlace(uri): navigate to that place's root (if it is not in prefs yet but a persisted permission exists, still try).
 - onClosed(): cancel/ignore pending work, shut down your executor (shutdownNow) and clear caches.
```
